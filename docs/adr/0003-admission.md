# 0003. 写入标准：一个准入问题、四条排除、宁缺毋滥

- 状态：采纳（2026-10-22）
- 日期：2026-10-22
- 相关：[questions.md](../questions.md) A2 · [research/a2-admission.md](../research/a2-admission.md) · [ADR-0002](0002-memory-layers.md)（两层）· [positioning.md](../positioning.md)（"会影响将来的东西"）

## 背景

定位里给出了记忆的定义："会影响将来的东西"。但这只是一个原则，还不能用来逐条判断。ADR-0002 把记忆分成两层：发生了什么、先验知识。A2 要回答的是：**发生了什么里的哪些东西，可以升级成先验知识？**

调研了 trace-memory、Pi OM、Magic Context、Hermes、Letta Code、mem0、claude-mem、CC auto memory 的写入规则。

## 考虑过的选项

1. **每个类别一套准入条件**，比如 Magic Context 给每一类配一个判定问题。
   - 问题：ADR-0002 已经决定类别只做标签。trace-memory 也走过这条路，后来退回到统一的准入问题。
2. **宁多勿漏，尽量都提取**（mem0）。
   - 问题：mem0 只有一层，漏掉就永远丢了。我们有"发生了什么"这一层兜底，不需要冒这个险。而且写多了会挤占上下文，也更容易写错。
3. **一个准入问题 + 排除项 + 宁缺毋滥**（选这个）

## 决定

**准入问题：**
> 如果下一次会话不知道这件事，会不会做错、重走被否决的路，或者需要我再解释一遍？

答"会"，才写成先验知识。

**四条排除：**

| 情况 | 怎么处理 |
|---|---|
| 能低成本重新得到：代码、git 历史、仓库里的文档、CLAUDE.md、ADR | 不复制内容。如果模型需要知道它存在，就写**一句理解 + 指针**（见下） |
| 只对当前任务有用：进度、临时待办、这次排查的中间状态 | 留在"发生了什么"里 |
| 已有知识已经覆盖 | 更新已有的那条，不新建 |
| 过程记录：查了哪些文件、跑了什么命令、失败的尝试 | 留在"发生了什么"里。失败尝试留下的**教训**不在此列，它可以通过准入问题 |

**仓库里已经记录过的东西：写一句理解 + 指针。** 比如：
> 记忆分两层：发生了什么、先验知识；类别只做标签。详见 docs/adr/0002-memory-layers.md。

记忆负责告诉模型"这件事已经定了，结论大概是什么，细节去哪看"，但不复制全文。

**偏向：宁缺毋滥。** 拿不准就不写，留在"发生了什么"里，以后需要时检索，或者在整理时再补。

**这次不定的：**
- 要多少证据才能写，比如说一次算不算、重复出现算不算 → A3
- 写成原则还是保留具体情况，写不写来源 → A3
- 记忆怎么过期 → A5
- 由谁来判断、什么时候判断 → B1

## 理由

- **准入问题是各家的共同做法，再加上我们自己的重点。**
  - trace-memory 问"忘了会有什么后果"，Pi OM 问"不知道它会不会做错决定、重复劳动、违反偏好"，Magic Context 问"会不会再踩一次同样的坑"。
  - "需要我再解释一遍"是我们加上的，直接对应愿景里的"默契"和成功标准里的"对齐成本"。
- **四条排除，各家都写过**，没有分歧。
- **宁缺毋滥有两个理由：**
  1. 有两层结构，漏掉的东西不会真的丢。
  2. 定位里写过，错误的记忆比没有记忆更糟。Pi OM 的说法是："过度提炼也是一种失真：它让临时细节看起来很持久，把真正需要的东西挤出去。"
- **选"理解 + 指针"，不选"完全不写"（Letta、Hermes、CC 的做法）：** 文档写得再好，模型不知道它存在，就不会去读，你问起来它可能按自己的理解回答，甚至重提已经否决的方案。也不复制全文，免得两边说法不一致。

## 后果

好的方面：
- 有了一条可以逐条判断的规则，后面写 worker 的提示词时可以直接用。
- 将来可以评测：拿历史上我纠正过的地方去回放（E4），看准入问题能不能把它们挑出来。

要付出的代价和风险：
- **"会不会做错"本身要靠模型判断，** 而判断会有偏差。具体表现要等实验和实际使用来校准。
- **宁缺毋滥可能漏掉"一次说过、很重要"的东西。** 这类东西能不能写，取决于 A3 定的证据门槛。
- **指针会失效：** 文件可能被移动、改名或删除。怎么检查指针还有没有效，在 A5 处理。

## 什么情况下推翻

- 实际使用中发现，需要我反复解释的东西，大量没有被写进记忆 → 说明标准太严，重新考虑偏向。
- 发现模型虽然拿到了指针，却很少去读 → 改为写入更多内容，或者在 C 段调整注入方式。
