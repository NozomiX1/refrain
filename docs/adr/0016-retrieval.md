# 0016. 检索：插件自带一个 MCP server，提供 search 和 read 两个工具，全文检索，范围是当前项目

- 状态：采纳（2026-10-23）；"原文检索要等脱敏做好才能上线"这个前提被 [ADR-0018](0018-storage-and-privacy.md) 取消（第一版不做脱敏）；接口被 [design.md](../design.md) 4.7 细化，并修订两处：可以用 `scope: "all"` 跨项目搜索（默认仍是当前项目），知识的所有版本也能搜到（标明当前 / 旧版本 / 已归档）；"插件自带一个 MCP server"被 design.md 7.2、7.4 修订：工具改由 mod 用 `$.tool.register` 注册，不再需要 MCP server，"什么时候查"写进 search 的工具说明
- 日期：2026-10-23
- 相关：[questions.md](../questions.md) C6 · [research/c6-retrieval.md](../research/c6-retrieval.md) · [ADR-0010](0010-extraction-depth.md)（原文是唯一事实来源）· [ADR-0012](0012-trimming.md)（渲染规则）· [ADR-0015](0015-context-assembly.md)（摘要属于项目）

## 背景

压缩时被挤成一行标题、或者被逐出的摘要，同一项目里其他会话的摘要，还有原文中的细节，都不放进上文，需要的时候去查（ADR-0015）。标注实验里，我问"…来着？"，想找的都是细节。

## 决定

1. **插件自带一个 MCP server，只提供两个工具：**
   - `search(关键词)`：在当前项目的摘要（标题、标签、正文）和原文里做全文检索，摘要的结果排在前面，每条都附上地址；
   - `read(地址)`：读一份摘要或一段原文。原文按 ADR-0012 渲染：去掉注入的内容，工具操作保留，但限制体积。

   主模型和 worker 用同一套工具。
2. **原文也要能搜到。** 摘要会漏掉细节，比如报错的原话。
3. **全文检索用 trigram 分词**（按连续的三个字符匹配），这样中文也能搜。
4. **"什么时候查"写进 MCP server 的说明**（照搬 trace-memory）：
   - 我提到以前的工作，而上文里没有，就去查；
   - 要说"我当时决定了什么"之前，先追到我的原话；
   - 记忆是过去的记录，和当前的文件或我最新的话冲突时，以后者为准。
5. **只搜当前项目。** "关于我"的知识是全局的，本来就注入了。

**第一版不做：**
- 向量检索；
- 每轮自动检索并提示（Magic Context 的做法）；
- 专门用来检索的子 agent。

**上线前提：** 原文检索要等 F3 的脱敏做好才能上线。原文里有我发过的密码。

## 理由

- **原文加 coding agent 自己去搜，表现最好。** LongMemEval-V2 中这种做法是 72.5%，最好的 RAG 只有 48.5%。CC 的主模型本来就是 coding agent，给它两个工具就够了。
- **trace-memory 只用全文检索，也能用。** 而且第一版里，搜不到的时候，模型可以换个说法再搜一次。
- **自动提示没有真实案例支撑。** 标注实验里的"…来着？"都是我主动问的。
- **CC 的 transcript 是带大量转义的 JSON Lines，直接 grep 很难读，**所以需要 `read` 先渲染一遍。

## 后果

好的方面：工具少、规则简单，不需要向量模型。

要付出的代价和风险：
- 同义词搜不到。比如我说"上线"，但当时写的是"部署"。
- 需要维护一份全文索引，原文的索引会比较大。存储方式在 F1 定。
- 模型可能该查的时候不查，只能靠说明里的"什么时候查"来约束。

## 什么情况下推翻

- 实测中经常因为同义词搜不到 → 加向量检索（Magic Context 的做法）。
- 出现"该查却没查"的真实案例 → 加每轮的自动检索提示。
