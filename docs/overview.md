# refrain 总览

> 一页看懂 refrain 现在是什么样、做到哪了。细节以 [design.md](design.md) 为准；为什么这样定、推翻过什么，见 [evolution.md](evolution.md)；逐日的讨论记录在 [log.md](log.md)。每做完一件事就更新这一页。
>
> 更新于 2026-10-26。

## 是什么

一个 Claude Code（CC）插件，让 CC 跨会话、跨项目地记住两类东西：**我是谁、喜欢怎么做**；**每个项目进行到哪了**。取代 CC 自带的 auto memory。

和别家不同的地方：每条记忆都带着出处，标明是我的原话、推断还是观察；压缩不调模型（交接是拼出来的，约 5 毫秒）；记忆的开销能量化。

## 怎么运转

```
我和 CC 对话（主会话）
  │ 每轮结束：新内容攒够 2 万字？
  ▼
书记员（后台子 agent，Haiku，推理强度 low）
  │ 读这批对话 + 已有的知识、摘要、现状 → 一次 submit 交上来 → 校验，不过就退回重交（最多 3 次）
  ▼
SQLite（~/.refrain/memory.db）：知识（带版本）、摘要、现状、原文索引
  │
  ├─► 新会话 / /clear / 压缩之后：简报（知识 + 现状）经 SessionStart 只给主会话
  ├─► 手动 /compact 或空闲压缩：交接（本会话的摘要 + 最后一段原文原样保留）替换上文，不调模型
  └─► 主模型需要以前的细节时：search / read 检索摘要、知识和原文
```

- **主模型只干活，不写记忆**；写记忆的只有书记员。我要改记忆就在对话里说，书记员下次整理时处理。
- **CC 的自动压缩和它自带的空闲压缩被拦下**；空闲压缩由配套的小插件 refrain-timer 按我们的条件发起。
- **会话关掉时没整理完的尾巴**，由同一项目里下一个会话的书记员补上（那个会话 1 小时没动静就算关了）。
- **积压太多时**（交接会超过上下文的一半），压缩交给 CC 原生的做法，记忆不受影响。
- 状态栏显示书记员在不在跑、花了多少；`/refrain` 打开面板看当前的记忆。

## 定下来的数

| 项 | 值 | 依据 |
|---|---|---|
| 书记员的模型和推理强度 | Haiku 5.5，low | E7：答题分和 Sonnet medium 在波动之内，额度约是它的 1/7 |
| 触发量 / 每批最多 | 2 万字 / 5 万字（渲染后） | E7：6 万字省额度但知识少四分之一、更容易交白卷；5 万字保证单次请求不越过 Haiku 的价格线 |
| 每次至少写一份摘要 | 是 | E7：书记员交过白卷 |
| 提交被退回 | 最多重交 3 次；同一会话连续失败 3 次就暂停 | |
| 摘要折叠 | 最新 8 份全文，更早的每 8 份折成标题，标题最多 160 条 | 待 E6 调 |
| 空闲压缩 | 缓存过期（1 小时）后、上文 ≥ 6 万 token、交接不超过上文一半 | |
| 书记员的额度消耗 | 每次整理约 $0.015（只算输入、缓存写入和输出）；整理两天的密集讨论约占周额度 0.3% | E7、额度核对 |

## 代码和测试

- `hooks/register.tsx`：mod，接 CC 的事件、注册工具和书记员、面板、状态。
- `core/`：Node 核心程序，读原文、书记员的准备和校验、存储、简报和交接、检索。零依赖，Node ≥ 24。
- `timer/`：refrain-timer，只负责空闲压缩的计时。
- 测试：核心 47 个（`npm test`），mod 5 个（`npm run test:mod`）。CC 自检清单 9 项在 2.1.310 上手动验证通过；CC 固定在 2.1.310，不自动升级。

## 进度

**做完了：** 第一版的全部部件（读取器、书记员、存储、简报注入、交接、检索、面板、状态栏、备份、`/refrain resume`、补尾巴）和 refrain-timer。

**实验做过的：**
- e1 消融：两三天的跨度上，问答题"只检索原文"不输 refrain，但 refrain 每次作答便宜约 5 倍、不用来回查；任务题（不问也该用上以前定的规则）refrain 明显更好。
- E7 书记员：定了模型、强度、触发量、上限；顺带查清了订阅额度怎么扣、书记员的缓存为什么命中不了。
- s1–s3 演练、e2 探测、s2 录制测试样本：端到端跑通，查出并修了一串 bug（压缩后误撤销、书记员收到主模型的简报、书记员从不收尾……）。

**发布前要做：**
- README、LICENSE（MIT）、`marketplace.json`、refrain-timer 的依赖声明、给别人用的状态栏脚本：已做（2026-10-27）；
- 建 GitHub 仓库 `NozomiX1/refrain`（公开），推一份用 `tools/export-public.sh` 导出的副本（README 里已填好 owner）；
- 开源前清理个人信息（哪些文档公开，待我定）；
- 正式版是否全局关掉 auto memory（现在只在用到的项目里关）。

**待做：**
- 状态栏和面板加一个"额度口径"的花费（只算输入、缓存写入和输出），和现在的 API 价并列；
- 交接、search、read 的返回和标准样例逐字比对的测试；
- 剧本测试（构造的小项目，可公开的回归测试）。

**实验和评测（都要花额度，跑之前先说）：**
- E6：摘要的粒度和长度；
- 离线回放评测：编造率、对齐成本、压缩保真率、接续准确率，对外展示的主要数字；
- 演练项目：比如给 Pi 做一个 subagent，跨几个会话真实地跑一遍；
- E7 剩下的：裁剪上限（不裁剪对比）、跨会话时书记员会不会去搜、B9（"待定"的边界）。

**待验证：** fork 之后书签和会话现状怎么接；补尾巴、白卷退回后重交在真实使用中的表现；CC 自带空闲压缩的触发值；D4（关掉后恢复、缓存已过期时，能否在第一次请求前换成交接）。

**推迟（有真实需要再做）：** CC 自检脚本和"未自检"提示；平时使用中的被动检查；回滚时 global 知识被别的会话改过的标记；以及 design.md 第 9 章列的其余各项（推断的确认、硬约束用 hook 强制、冷启动、Dreamer、脱敏……）。
