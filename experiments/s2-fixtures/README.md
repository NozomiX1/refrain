# s2：录测试样本，顺带跑一遍 CC 自检

对应 design.md 7.13 的"测试样本用 tmux 现造"和 CC 自检清单。同时验证简报改走 `SessionStart` 之后（e2）refrain 自己的表现。

做法：在 `work/proj/` 建一个只有三个小文件的 git 仓库（内容是我们写的，可以公开），用 `tools/cc-start.sh` 开交互式 CC 2.1.310（Haiku），加载 refrain 和 refrain-timer。数据目录指到 `work/refrain-home/`，触发量调到 800 字。按下面的台词跑，录下来的两份主会话 transcript 用 `tools/scrub-transcript.py` 清理后存成 `test/fixtures/recorded-a.jsonl`、`recorded-b.jsonl`，读取器的输出存成同名的 `.entries.txt`，由 `test/recorded.spec.ts` 逐字比对。原始 transcript 在 `raw/`，只在本机。

**清理做了什么：** 删掉每次请求的完整副本（里面有系统提示、邮箱、环境信息）和几种读取器不看的记账行；附件在父链上，留下行、清空内容；主目录路径、用户名、邮箱换成 `/home/user`、`user`、`user@example.com`。脚本最后列出残留，再人工抽查一遍。

## 台词

| 轮 | 做什么 | 要录到的 |
|---|---|---|
| 1 | 打一句话，中间用 tmux 的 `paste-buffer -p` 真实地粘贴一段 | 粘贴标签 |
| 2 | 让它并行读两个文件 | 并行工具调用（Haiku 这次是一个接一个读的，没录到并行，手工样本里有） |
| 3 | 让它跑一个要权限的命令，弹窗里选 No | 我手动拒绝 + 随之而来的打断 |
| 4 | 让它写长文，开始输出后按 Esc | 回答到一半的打断（太早按 Esc，CC 会把消息退回输入框、不留记录，试了三次） |
| 5 | `seq 1 30000` | 超大工具输出（它自己加了 `\| tail -n 1`，没录到） |
| 6 | 起一个 Explore 子 agent | 子 agent 的调用和完成通知 |
| 7 | `/refrain resume` | 插件命令（不进对话，读取器正确地丢掉） |
| — | `/compact 重点保留拒绝和打断` | 我们接管的压缩、原样放回的尾巴副本 |
| 8 | 压缩后问"刚才我拒绝了什么命令" | 压缩后接着做 |
| — | `/clear`，再问一句 | 新会话 |
| — | 退出，`--resume`，再说一句 | 恢复会话 |

## 结果

**简报（SessionStart）在 refrain 里：** 两份主会话各 1 份（第一份在压缩之后，开头还没有记忆所以不注入；第二份在 `/clear` 时，恢复后没有重复）；两次书记员和 Explore 都是 0 份。

**读取器在真实记录上发现的问题（已修）：** 粘贴的结束标签也带编号（`</pasted_content id="e1b4">`），原来的规则只认不带编号的，粘贴的内容会被当成我的原话。手工样本也改成了真实的写法。

**书记员：** 第一次运行在 0.18 秒内就失败了，`$.agent.spawn` 没返回 agent 编号，书记员根本没起来；当时我的脚本在上一轮结束后马上发了下一句。下一轮重试成功（4 份摘要都对）。原来代码不记 spawn 返回了什么，已改为把原因写进这次运行的失败原因。

**压缩：** `preTokens` 48,705 → `postTokens` 1,953，208 毫秒；压缩后问"刚才我拒绝了什么命令"答对。
