# B1 调研：谁来写记忆

> 目的：回答 B1：记忆由主模型在对话中当场写，还是由后台 worker 写，还是两者都有。还要覆盖 ADR-0007 的要求："记住……"必须立即生效。
> 日期：2026-10-23
> 证据等级：**S** = 源码或项目自带文档（scratchpad 里的克隆）· **R** = 官方文档。

## 1. 各家的做法

| 项目 | 主模型当场写 | 后台 worker 写 | worker 什么时候跑 | worker 用什么模型 |
|---|---|---|---|---|
| **CC auto memory**（R） | 写。"记住……"由它直接写进去 | auto-dream 只负责整理（灰度中，见 a6 第 4 节） | — | — |
| **Hermes**（S） | 写。主模型手里有 memory 工具 | 写。fork 出一个 agent 回看对话，问"有没有值得存的" | 默认每 10 轮一次（`nudge_interval`） | 默认和主模型相同。fork 继承主会话的缓存，回看整段对话算缓存读取，比较便宜；如果换成别的模型，缓存失效，就改为只喂一份摘要 |
| **Letta Code**（S） | 写。主 agent 自己改记忆块 | 写。reflection / sleeptime 子 agent | 默认每 25 步一次，也可以设成压缩时触发 | 可配置。合并有两种模式："自动"直接生效，"显式"交给主 agent 来合并 |
| **Magic Context**（S） | 写。主模型有 `ctx_memory`（长期知识）和 `ctx_note`（延后的打算；"smart note" 带条件，由 dreamer 盯着条件是否满足） | 写。historian 负责压缩和提取，dreamer 负责整理 | 按上下文用量触发 | 必须单独配置 |
| **claude-mem**（S） | 不写 | 写。PostToolUse 把每次工具调用交给 observer，Stop 和 SessionEnd 时做总结 | 每次工具调用后 | 用 Agent SDK 单独调用，模型分档配置 |
| **trace-memory**（S） | **不写** | 写。Noter 负责提取，Dreamer 负责整理 | 每轮结束时检查，新内容累积约 10k token 就触发 Noter；待处理内容约 5k token 就触发 Dreamer | Noter 默认用新开的子 agent，可以选 fork（继承上下文和缓存）；Dreamer 一律用新开的子 agent。在 CC 上，fork 通过插件函数接口 `$.agent.spawn({subagentType: "fork"})` 启动，子 agent 通过 Agent SDK 启动 |
| **LangMem**（S） | 两种都提供 | 两种都提供 | — | — |

LangMem 的概念文档对两种方式的权衡写得最清楚：
- **当场写**："实现简单，更新能立即生效"，但"会增加用户能感觉到的延迟，而且给 agent 完成用户需求又多加了一道障碍"。
- **后台写**："不拖慢交互，也不增加 agent 选择工具的负担"，而且"召回率更高"。

## 2. 共同模式

- **大多数项目两种都做：** 主模型留一个窄入口，后台负责大部分提取。只有 trace-memory 和 claude-mem 完全不让主模型写。
- **当场写的入口都很窄：** 一个工具，一句话。Hermes 曾经出过问题：两个存储都让模型自己选，结果同一件事被写进了两个地方（issue #30220，见提示词注释）。
- **后台触发都靠"量"：** 按轮数（Hermes 10 轮、Letta 25 步）、按 token 数（trace-memory），外加压缩和会话结束这两个时点。没有一家按"内容重要"来触发，因为判断重要本身就要调一次模型。
- **fork 和新开子 agent 是成本上的取舍：**
  - fork 和主会话同模型，能复用缓存，回看完整上下文很便宜；但用的是贵模型，而且只能看到当前会话。
  - 新开子 agent 可以用便宜模型，但要自己拼材料，缓存是冷的。
  - 这个问题留给 B4。

## 3. 对照我们已经定下的规则

| 规则 | 对"谁来写"的要求 |
|---|---|
| ADR-0004 证据只认我本人，存储时保留引用链 | 写入方必须能拿到原话和消息位置。worker 读 transcript 能做到；主模型当场写也能做到，前提是由工具自动记录消息位置，不靠模型自己填 |
| ADR-0006 写入时裁决 | 每次写入都要先看相关的旧知识，判定保留、过期还是替换。这是重活，不适合放进主模型的回合里 |
| ADR-0007 "记住……"立即生效 | 必须有一条当场的通道。"立即"的实际含义是：**在压缩或会话结束之前落盘，下次会话一定能看到**。当前会话里那句话本来就在上下文中 |
| ADR-0008 现状在压缩前和会话结束时重写 | 天然是 hook 触发的后台任务 |
| 差异点 3 低成本 | 主模型通常是最贵的模型，写记忆的 token 越少越好 |

## 4. 一个 CC 特有的事实

auto memory 关掉以后，CC 的系统提示里就没有"记住时该怎么写"这一段了。主模型听到"记住……"时，只会照我们注入的说明去做。所以那条当场通道的说明，要由插件自己注入（SessionStart，或者写在工具描述里）。
