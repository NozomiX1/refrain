# 0014. 识别我本人的话：按 CC 自带的来源字段建白名单，其余一律算上下文

- 状态：采纳（2026-10-23）
- 日期：2026-10-23
- 相关：[questions.md](../questions.md) B8 · [research/b8-user-authorship.md](../research/b8-user-authorship.md) · [ADR-0004](0004-evidence-and-hypotheses.md)（证据只认我本人）· [ADR-0011](0011-v1-scope-cuts.md)（第一版简化）· [ADR-0012](0012-trimming.md)（注入的内容丢掉）

## 背景

ADR-0004 规定证据只认我本人的条目，ADR-0012 规定裁剪时丢掉注入的内容。这两条规则的前提是：能分清 transcript 里哪些话是我写的。

麻烦在于，CC 的 transcript 里 role 为 user 的条目，大多不是我写的：工具结果、命令回显、系统元信息、子 agent 的提示词、压缩摘要等，都记成了 user。标注实验里还有一个真实例子：我贴进来一段别的 AI 写的方案，只有最后一句是我自己的话。

我统计了本机 CC transcript 里 4604 条 role 为 user 的条目（见 research/b8-user-authorship.md），发现 **CC 自己会给每条消息标上来源**。

## 考虑过的选项

1. 黑名单：按内容特征排除不是我写的（标注实验用的就是这种办法）。
2. **白名单：只认 CC 明确标为"human"的条目**（选这个）。黑名单作为兜底。

## 决定

**1. 算作我的话（可以当证据）：**
- `origin.kind = "human"` 的条目（`promptSource` 为 `typed` 或 `queued`），去掉其中 `<pasted_content>` 包着的部分；
- 斜杠命令后面我写的参数。

**2. 算作我的操作（也可以当证据）：**
- 打断（`[Request interrupted by user]`）；
- 我手动拒绝的工具调用（`toolDenialKind = user-rejected`）。**auto mode 分类器拦下的（`automode-blocked`），以及按配置自动拒绝的，都不算。**

**3. 其余一律算上下文，不当证据。** 粘贴的内容可以帮 worker 理解我在回应什么，但不算我的立场。

**4. 提示词规则：** 我转述别人的话（比如"Codex 说……"），不算我的立场。

**5. 兜底：** 这些字段 CC 没有写进文档。如果某个会话里一条带 `origin` 的条目都找不到，就退回黑名单过滤，同时在日志里报警，不能悄无声息地出错。

**第一版不做：**
- 我在权限弹窗里点"允许"的记录（`permissionDecision.source = user_temporary`）：没有真实案例说明它有用。
- Pi 和 Codex 的格式：第一版只做 CC。

## 理由

- **白名单比黑名单稳。** 黑名单要列举所有"不是我"的情况，CC 每加一种注入，黑名单就得跟着补。白名单只认一种明确的标记，出错时也是偏保守：漏认我的话，最多少一条证据；把别人的话当成我的，就违反了 ADR-0004。
- **数据对得上。** 647 条 human 条目，和标注实验里人工认出来的数量一致，误差来自命令的计法不同。超过 3000 字符、又没有粘贴标签的长消息，一条都没有。
- **"拒绝"一定要看字段。** 同样是拒绝，有 2 次是我拒绝的，有 4 次是分类器拦下的，只看结果分不出来。
- **粘贴有标签。** 标注实验里那段别的 AI 写的方案，就包在粘贴标签里。

## 后果

好的方面：
- 规则简单，由代码判定，不调模型。
- ADR-0004 和 ADR-0012 有了能落地的判定办法。

要付出的代价和风险：
- **依赖 CC 没有写进文档的字段。** CC 一升级，这些字段就可能变。兜底和报警可以防止悄悄出错，但不能保证不出错。需要准备一份测试样本，每次 CC 升级后跑一遍。
- **短的粘贴可能没有标签。** 我手动敲进去的别人的话，也认不出来。这类情况只能靠第 4 条提示词规则来补。
- **只验证了 CC 2.1.295–2.1.308。**

## 什么情况下推翻

- CC 去掉或者改掉了 `origin` 字段 → 换成新字段，或者只用黑名单。
- 发现有不少粘贴没有标签，被 worker 当成了我的话 → 补充内容层面的判断规则。
