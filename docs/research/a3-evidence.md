# A3 调研：用户模型的证据，原话还是推断，以及来源要不要写

> 目的：回答 A3 的三个子问题：
> (a) 用户模型只依据我说过的话，还是也从我的行为推断？
> (b) 证据要多少才够：说一次算不算，重复出现算不算？
> (c) 记忆里写不写来源？
> 日期：2026-10-22
> 证据等级：**F** = 论文全文（arXiv HTML，部分论文很长，只读了前 10 万字符）· **S** = 源码和提示词。

## 1. 论文

| 论文 | 和 A3 有关的发现 | 等级 |
|---|---|---|
| **AdaMem** 2606.21144 | 比较两种条件：一种明确告诉 agent 用户的偏好，一种只给纠正、让 agent 自己推断。到第 10 周，策略和真实偏好的吻合度：明确 95.0%，推断 63.3%。推断条件下，有实质改动的更新里，**46.1% 是朝偏离真实偏好的方向改的**（明确条件下是 56.8% 朝正确方向）。原因："模型必须自己推断潜在的偏好，因此更容易写出**过宽或方向错误的规则**"；"直接的偏好陈述带来更可靠的学习" | F |
| **Personalization Mirage** 2608.04570 | **更正之前扫描时的说法：41.6% 是"超出证据"的比例，不是编造率。** 其中编造（毫无依据）占 31.1%，套刻板印象占 10.5%。这些发生在**生成**时：只给模型 3 条用户事实，再让它做个性化任务，它会自己补充。如果要求模型"列出推断并给每条附上证据"，超出证据的比例只有 0.7–4.6%。作者的建议（没有实验验证）：按认识状态给信息打标签，分成用户陈述的、推断的（附证据链接）、没有证据生成的；"**没有链接的推断要当作假设，而不是事实**"；"偏向结构化的来源，而不是激进的摘要" | F |
| **TRACE** 2606.13174 | 规则来自"纠正信号"，包括持久偏好、重复的错误、工作流上的摩擦，后两种不完全是明说的。**规则的适用范围由模型推断**。用模拟器生成的纠正，只有 0.668 能还原出人工标注的偏好。用 Mem0 存储时，合规率只有 42.5%；把规则编译成运行时检查后，升到 70.1%："能访问到并不会让偏好具有约束力"。论文**没有测量误拦截**，规则被错误地 Supersede 后要手动回滚 | F |
| **Belief-Based Memory** 2606.22030 | **"重复出现"可以被攻击者利用：** 只按多数票计算时，攻击者写 10 条假信息就能推翻 4 条可信的。如果按来源渠道限定可信度上限，攻击成功率降到 0%。**措辞也能造假：** 权威语气的可信度评分是 0.96，含糊语气是 0.25，所以可信度不能看内容，要看来源。代价是：如果来自低可信渠道的纠正本身是对的，也会被压下去 | F |
| **ToM-SWE** 2510.21903 | 给编程 agent 做用户建模，会从**措辞、语气、详略、提问方式**推断偏好。存储分三层：原始会话 → 单次会话的模型 → 跨会话的用户模型。每条建议带 0–1 的置信度，只作为参考，不确定时会问用户。17 名开发者用了 3 周，86% 的建议被全部或部分采纳。但用户**没有办法查看、修正或让某条偏好过期** | F |
| **Beyond Recall** 2605.28969 | 只记住"事实"不够，还要有"解读层"：这个人做判断的模式。行为规范（约 7k token）能拿到原始语料（16 万 token）约 75% 的收益。换成**另一个人的**行为规范，效果反而是负的（Δ = −0.25）。每条模式都能追溯到原文段落，但不清楚这些来源会不会进 prompt。研究对象是历史人物的自传，不是真实用户 | F |
| **Verification Horizon** 2606.26300 | 隐式信号很嘈杂：只有用户**直接在 agent 的输出上继续工作**，才算接受；用户新提出偏好，既不算正反馈，也不算负反馈 | 搜索摘要 |

## 2. 项目

| 项目 | (a) 推断 | (b) 证据门槛 | (c) 来源 |
|---|---|---|---|
| **trace-memory** | 允许，但要区分："用户对自己偏好的陈述是权威的；**问句不是立场**"；"提议不是决定" | **重复只提示复查**，不扩大适用范围，也不把 agent 的要求变成用户的裁决 | 存储：每条知识都引用 fact，fact 引用原始消息。注入：知识正文 + 支撑 fact 的 ID，不展开原文 |
| **Magic Context** | 允许：从行为观察用户的沟通风格、专长、决策方式 | **至少 3 条相似的观察**，候选保留 30 天，过期作废（"真实的特质会在几天到几周内反复出现"）。只收跨项目通用的特质 | 画像条目记录候选来源，注入时不带来源 |
| **Letta Code** | 允许 | "只根据**一个模式或一条明确指令**更新，不根据单个含糊的事件" | **常驻记忆不写来源**：不写名字、日期、引语、事件经过。事件留在消息历史里，改动原因写在 git 提交信息里。理由是：写成原则才能推广；模型会模仿示例里的细节，包括要它避免的那些 |
| **CC auto memory** | feedback 类既记纠正，也记"你认可过的做法" | 没有规定 | 只要求写 **Why**，不要求引用原文 |

## 3. 归纳

1. **推断有价值，但更容易错。**
   - 价值：愿景里的"了解我的思考方式"、Beyond Recall 的解读层，都离不开推断；ToM-SWE 的推断也被开发者普遍接受。
   - 风险：AdaMem 是目前最直接的对照实验，推断出的规则有将近一半方向偏了，典型的错误是"过宽"。
2. **最大的风险不在"推断"本身，在"推断被当成事实"。** Personalization Mirage 发现，要求模型给推断附上证据时，它相当忠实；问题出在没有证据约束的生成。所以关键是**给每条记忆标上认识状态**，并且要求推断必须有证据链接。
3. **"重复出现"要看是谁在重复。** 只数次数可以被攻击（Belief-Based Memory），所以只能数用户本人的消息，不能数工具输出、网页或 agent 自己说过的话。
4. **来源的问题，可以拆成"存"和"注入"两件事：**
   - 存储时保留完整的引用链：要做忠实、要做归因（差异点 2）、要防投毒、要让用户能修正，都离不开它。
   - 注入时只给原则，不给故事：Letta 担心模型过度模仿事件细节，这个担心成立；trace-memory 注入时也只带 ID。
