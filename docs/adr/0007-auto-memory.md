# 0007. 和 CC auto memory 的关系：取代它，先导入作为线索；实验期按项目关，成品全局关

- 状态：采纳（2026-10-22）；关闭 auto memory 的前提被 [ADR-0009](0009-writer.md) 修订：从"'记住……'立即生效"改为"worker 保证每段都会被处理"；第一版简化见 [ADR-0011](0011-v1-scope-cuts.md)：第一步"导入"去掉（属于冷启动）
- 日期：2026-10-22
- 相关：[questions.md](../questions.md) A6 · [research/a6-auto-memory.md](../research/a6-auto-memory.md) · [ADR-0004](0004-evidence-and-hypotheses.md)（证据）· [ADR-0006](0006-lifecycle.md)（写入时裁决）

## 背景

CC 自带 auto memory，默认开启。由主模型在会话里自己写，分 user / feedback / project / reference 四类，按仓库存放，每个会话加载 `MEMORY.md` 的前 200 行。我现在就在用它。定位里已经定了和 CLAUDE.md 共存，但还没定和 auto memory 是什么关系。

## 考虑过的选项

1. **共存**（trace-memory 默认是这样；claude-mem 的交互式安装默认也保留）
   - 问题：两个系统各写各的，说法可能互相矛盾。STALE 发现，新旧两种说法同时摆在模型面前，它照样会选错。而且 auto memory 写进去的东西没有证据链，会稀释"忠实"和"归因"。
2. **建在它上面：把它的目录当作我们的存储和注入通道**
   - 问题：它只要开着，主模型就会自己往里写，还是两个写入者。它也只按仓库划分，没有跨项目，没有历史。
3. **直接关掉，不管已有内容**
   - 问题：我已经在用它，已有的内容会丢。而且"记住……"马上生效这个能力，插件还没覆盖。
4. **取代它：先导入作为线索，补上必要的能力，再关**（选这个）

## 决定

**取代 auto memory，分三步：**

1. **先导入。** 把已有的 auto memory 内容作为**线索**导入，而不是当作结论。对每一条，都去历史 transcript 里找支撑它的我本人的条目：
   - 找到了，按 ADR-0004 入库，标为原话或推断；
   - 找不到，作为假设，等以后问我（C5）。

   具体流程并入 B7（冷启动）。原文件不删除。
2. **补上能力。** 我说"记住……"时要能立即生效（B1）。在这个能力做好之前，不关 auto memory。
3. **再关。**

**关的范围：**
- **实验期：按项目关。** 只在启用插件的项目里设置 `"autoMemoryEnabled": false`，其他项目照常使用 auto memory。这样不影响还没接入插件的项目，也方便做对照。
- **成品：全局关**（`CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 或用户级设置）。**跨项目是这个插件的关键特性**，而 auto memory 只按仓库划分。成品必须接管所有项目，只按项目关的话，跨项目的知识就会和各项目的 auto memory 互相打架。

**评测：** 保留"开着 auto memory、不装插件"作为对照组（E5）。这是我现在的真实基线。

## 理由

- **它满足不了我们已经定下的规则：** 没有证据链（ADR-0004）；没有跨项目和会话级的作用域（ADR-0002/0006）；直接改写文件，没有历史（ADR-0006）；不知道具体用了哪条（差异点 2）；写记忆花的是主会话的 token（差异点 3）。
- **两个系统并存会互相干扰。** Magic Context 在 OMP 上也是直接关掉自带记忆，理由是"第二个记忆注入器会让召回和保留重复"。claude-mem 的代码注释称它是"用户控制之外的影子状态，争抢上下文 token"。
- **导入作为线索，而不是结论。** 这些内容是 Claude 写的，按 ADR-0004 不能算我的原话。但它们指出了"哪些东西曾被认为值得记"，作为线索很有价值。claude-mem 也是直接导入、不调模型。我们多做一步：回到 transcript 找证据。
- **实验期按项目关、成品全局关，** 兼顾了两个需求：开发阶段要能做对照、不影响其他项目；成品阶段要实现跨项目，必须由一个系统统一负责。

## 后果

好的方面：
- 记忆只有一个来源，不会出现两套说法。
- 有一个现成的对照组，而且是我真实在用的基线。

要付出的代价和风险：
- **"记住……"立即生效** 成了插件必须有的能力，B1 要覆盖。
- **实验期两套系统同时存在：** 启用插件的项目用插件，其他项目用 auto memory。跨项目的知识在这个阶段只能在启用插件的项目之间流动。
- **auto memory 的文件和插件的存储，在导入后可能慢慢不一致。** 导入只做一次；之后在关掉 auto memory 的项目里，原文件不再更新。
- **我在 CC 设置里改过的东西可能被覆盖。** 全局关的时候，要保留我已有的其他设置，并且可以撤回。
- **CC 官方可能会改进 auto memory。** 比如加上跨项目、整理或来源。ADR-0001 已经列为推翻条件之一。

## 什么情况下推翻

- CC 官方的 auto memory 补上了跨项目、整理和来源 → 重新评估是取代、共存还是建在它上面（同时触发 ADR-0001 的推翻条件）。
- 实验发现，对照组（只开 auto memory）和插件的差距很小 → 回到定位，重新讨论项目的必要性。
