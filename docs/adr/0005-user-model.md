# 0005. 用户模型：不单独存储，加"关于我"标记，五个维度做检查清单

- 状态：采纳（2026-10-22）；第一版简化见 [ADR-0011](0011-v1-scope-cuts.md)："关于我"退化为普通标签，五个维度保留为提示词里的检查清单
- 日期：2026-10-22
- 相关：[questions.md](../questions.md) A4 · [research/a4-user-model.md](../research/a4-user-model.md) · [ADR-0002](0002-memory-layers.md)（两层 + 两个轴）· [ADR-0004](0004-evidence-and-hypotheses.md)（原话与推断）

## 背景

ADR-0002 把"用户要不要单列一类"推迟到这里。老 spec §7.7 提出用户模型要建模"代码风格、沟通方式、决策习惯、技术水平……"，但没有定下来。愿景里的说法是"我的偏好、习惯和思考方式"。

## 考虑过的选项

1. **单独存一套用户画像**（Magic Context、Hermes、Letta、CC 的做法）
   - 问题：ADR-0002 已经用作用域和稳定性组织了所有先验知识，再单独存一套，就会出现两套规则。而且偏好常常和具体场景绑在一起，硬拆开反而丢了上下文。
2. **完全不区分**（trace-memory：用户偏好就是 global 的 constraint）
   - 问题：ADR-0004 的严格规则落不到具体的条目上；我没法一次看到"Claude 眼中的我"；差异点 1 也没法评测，因为不知道哪些条目属于用户模型。
3. **不单独存储，加一个"关于我"的标记**（选这个）

维度方面，考虑过用固定 schema（比如 LangMem 的画像、User as Code 的类型化对象），没有采用。

## 决定

**"关于我"标记：** 关于我的先验知识和其他知识放在一起，同样用作用域和稳定性两个轴，大多数是 global。另外标上"关于我"。这个标记用来：
- 确定 ADR-0004 的规则作用在哪些条目上：区分原话和推断，证据只认我本人的条目；
- 让我能一次看到并修正"Claude 眼中的我"；
- 评测差异点 1：编造率和遵从率都按这部分条目来算。

**五个维度，做检查清单和标签，不做固定槽位：**

| 维度 | 例子 | 对应愿景 |
|---|---|---|
| 背景与专长 | 熟悉什么、不熟悉什么 | 了解我 |
| 沟通方式 | 中英混合交流 | 偏好 |
| 做事方式 | 先定位再决策；调研要带目的；实验只做必要的 | 习惯 |
| 价值与判断 | 认真做、记录过程；宁可慢一点也要想清楚 | 思考方式 |
| 目标与处境 | 让 LLM 像人一样拥有长期记忆 | 了解我 |

维度只用来提示 worker 该留意什么，以及在展示时分组。一条知识可以不属于任何一个维度。

**不进用户模型的：**
- 和某个项目绑定的偏好 → 放进那个项目的知识，作用域是 project。
- 一时的情绪、只和当前任务有关的不满 → 留在"发生了什么"里。
- 和一起工作无关的私人信息 → 不写。隐私规则见 F3。

## 理由

- **一个标记就够用，不必单独存储。** 单列能带来的好处，一个标记都能提供：规则精确地作用在用户模型上、可以单独审查、可以单独评测。同时又不用维护两套规则，ADR-0002 的结构也不受影响。
- **五个维度覆盖了各家的做法和愿景：**
  - CC、Hermes、Letta：角色、背景、目标；
  - ToM-SWE、Magic Context：沟通和交互风格；
  - Magic Context、Letta：工作风格、决策模式；
  - Letta、Beyond Recall：看重什么、怎么判断。

  愿景里的偏好、习惯、思考方式也都有对应的维度。
- **不做固定槽位，是吸取别人的教训。** User as Code 增量改写类型化 schema 时，性能掉了 10 个百分点，模型会把信息塞进备注字段；trace-memory 和 Magic Context 都删减过类别。
- **排除项是各家的共识：** Magic Context 明确排除项目相关的偏好、框架选择和一时的情绪；Hermes 把任务相关的偏好放进 skill。

## 后果

好的方面：
- 可以提供一个"Claude 眼中的我"视图，按维度分组，并标明哪些是原话、哪些是推断。
- 差异点 1 的评测有了明确的对象。

要付出的代价和风险：
- **"关于我"和"关于项目"的边界会模糊。** 比如"这个项目我想认真做"，说的是我，作用域却是 project。处理方式：标"关于我"，作用域设为 project。两个属性是独立的。
- **"目标与处境"变化快，** 多半是待定状态，需要定期回看（A5）。
- **ADR-0004 要求"只认我本人的条目"，** 但 CC transcript 里标成 user 的条目不一定是我写的（Letta 的提醒）。怎么识别作者见 B8。

## 什么情况下推翻

- 发现关于我的知识和其他知识，在写入、整理、注入上需要的规则差别很大，一个标记不够用 → 改为单独存储。
- 实际使用中，某个维度几乎从来没有内容，或者大量知识都放不进五个维度 → 调整维度。
