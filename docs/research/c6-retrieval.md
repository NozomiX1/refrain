# C6 调研："发生了什么"怎么检索

> 目的：回答 C6。主模型和 worker 怎么在项目的摘要和原文里找东西。
> 日期：2026-10-23
> 证据等级：**S** = 源码 · **R** = 官方文档 · **P** = 论文。

## 1. 需求

- 我问"…来着？"时，要找的是细节：过去的 bug、测过什么、当初怎么讨论的、某个数字（见标注实验）。
- 压缩时被挤成一行标题或被逐出的摘要，要能找回来（ADR-0015）。
- 新会话里，要能查到同项目其他会话做过的事（ADR-0015：摘要属于项目）。
- worker 需要细节时，按地址回读原文（ADR-0012）。

## 2. 各家的做法

| 项目 | 搜索方式 | 读原文 | 什么时候搜 |
|---|---|---|---|
| **trace-memory**（S） | 一个 search 工具，后端是 SQLite FTS5，**trigram 分词**（按连续三个字符匹配，中文也能用）。**不用向量检索** | 用虚拟路径，比如 `trace://raw/S1/T3#E2`。拦截 CC 原生的 Read 工具，返回渲染好的内容 | 系统提示里有一段"什么时候查"：会改变下一步时才查；用户提到之前的工作时查；要写"用户决定了什么"时，先追到用户的原话。另有一句："记忆是过去的记录；和当前文件、最新消息冲突时，以后者为准" |
| **Magic Context**（S） | 一个 `ctx_search` 工具，同时搜记忆、对话原文、git 提交和笔记。**向量检索**（默认用本地的 MiniLM 模型），全文检索兜底 | — | 另有"自动检索提示"：每轮在后台搜一次，有相关内容就给主模型递一句"模糊的回忆"，默认开启 |
| **Letta**（R） | 文件工具：grep、语义搜索、打开文件 | 同一组工具 | agent 自己决定 |
| **LongMemEval-V2**（P） | 原文文件，加一份说明，交给 coding agent 自己去搜，得分最高（72.5%），但每题要 2–3 分钟 | — | — |

## 3. CC 这边的条件（R）

- 插件可以自带 MCP server。server 的 instructions 会进系统提示，上限 4096 字符。
- MCP 工具默认延迟加载：会话开始时只加载工具名和 server instructions，用到的时候才加载完整定义。
- CC 的 transcript 是 JSON Lines 格式，直接 grep 很难读：里面全是转义字符，还混着大量注入的内容。需要一个渲染步骤。
