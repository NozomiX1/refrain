# A7 调研：接续工作状态和待办，算不算记忆

> 目的：回答 A7。上次做到哪、还剩什么、卡在哪，以及待办，放在哪一层？
> 日期：2026-10-22
> 证据等级：**R** = 官方文档（2026-10-22 抓取）· **S** = 源码和提示词。

## 1. CC 本身已经提供的（R）

| 机制 | 做什么 | 范围 |
|---|---|---|
| `--continue` / `--resume` / `/resume` | 从 transcript 恢复整段对话。如果压缩过，从最后一次压缩的摘要接着走。还会恢复正在进行的 goal、会话内的定时任务、权限模式 | **同一个会话** |
| 会话回顾（`/recap`） | 你切走再回来时，给一行"你不在时发生了什么" | 同一个会话 |
| 会话标题、`/rename` | 选择器里可以按名字找到旧会话 | 找会话用，不提供内容 |
| 新会话 | 只自动加载 CLAUDE.md 和 auto memory，**不会自动拿到上一个会话的任何内容** | — |
| transcript 保留期 | **`cleanupPeriodDays` 默认 30 天**（文档原文："Change the 30-day retention"），之前一直没核实 | — |

所以 CC 已经覆盖了"接着同一个会话做"。**真正的空白是：新开一个会话，接着做同一个项目里没做完的事。**

## 2. 各家的做法（S）

| 项目 | 进度和待办放在哪 | 新会话能拿到吗 |
|---|---|---|
| **trace-memory** | 先验知识的 `open` 类。写法要求："进度服务于接续：保留必要的目标、最新的有证据的状态、关键的待解决点、去哪查；保留已经说定的下一步和执行边界；**不要编计划，不要堆砌能查到的过程记录**"。另有"goal 不含进度" | 能，作为知识注入 |
| **claude-mem** | 会话摘要，字段有：请求、调查了什么、学到了什么、完成了什么、下一步、备注。另有 `work_state_write` 专门存待办，可以用 `CLAUDE_MEM_WORK_STATE_ENABLED=false` 关掉，"留给自己管理工作状态的宿主" | 能，开会话时注入最近的时间线 |
| **CC auto memory** | `project` 类："进行中的工作、截止日期" | 能 |
| **Hermes** | **不进记忆**："任务进度、做完的工作、临时待办，用 session_search"。待办列表只在当前会话有效，**压缩后会重新注入**（"[你的待办列表在压缩中保留了下来]"） | 不能，要自己去搜 |
| **Letta Code** | **不进常驻记忆**："不写当前状态、最近的活动"；需要时用 recall 子 agent 搜历史 | 不能，要自己去搜 |
| **Magic Context** | 绕开了这个问题：主打"一个会话用一辈子"，用压缩后的会话历史让同一个会话一直接下去 | 不需要新会话 |

## 3. 归纳

1. **要分清三种"接续"：**
   - 同一个会话接着做：CC 原生就支持。
   - 会话内跨压缩：这是 D 段的事。Hermes 的做法是压缩后重新注入待办。
   - **新会话接着做同一个项目：** 这才是 A7 真正要解决的。
2. **分歧的本质是：** 接续状态变化快、过时也快。注入它，下个会话能马上接上，但有误导的风险，还要花维护成本。不注入，就得靠模型想起来去搜。
3. **trace-memory 的写法要求有一个关键点：只保留"接着做需要的"**，也就是目标、最新状态、待解决点、已经说定的下一步、去哪查。过程本身留在原文里。
4. **很多项目自己就有进度记录。** 比如这个项目的 `questions.md` 和 `log.md`，还有 git 提交和分支。按 ADR-0003，记忆只需要写一句理解加一个指针。
