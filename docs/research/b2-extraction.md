# B2 调研：重度提取，还是少提取、多存原文

> 目的：回答 B2。记忆是从对话里大量提取成条目，还是少提取、多保留原文，用的时候再去检索。
> 日期：2026-10-23
> 证据等级：**P** = 论文 · **R** = 官方文档或博客 · **S** = 源码。

## 1. 证据

### LongMemEval-V2（arXiv 2605.12493，P）

测的是 web agent 能不能从大量历史操作轨迹里学到"这个环境的知识"。规模：每题 2500 万到 1.15 亿 token 的历史，共 451 题。回答问题的模型固定为 Qwen3.5-9B，各个记忆系统只负责找出材料交给它。

| 系统 | 平均准确率 | 每题延迟 |
|---|---|---|
| 不检索 | 1.3% | 0 秒 |
| RAG（只检索原文切片） | 40.5% | 0.1 秒 |
| RAG（原文切片 + 笔记） | 48.5% | 0.2–0.3 秒 |
| AgentRunbook-R（写入时提取出三类：原文切片、状态变化事件、操作笔记） | 57.8% | 约 26 秒 |
| Codex（coding agent 直接搜原文文件） | 69.3% | 约 180 秒 |
| AgentRunbook-C（原文文件 + 一份使用说明 + 目录清单 + 辅助脚本，交给 coding agent 去搜） | **72.5%** | 约 110–140 秒 |

消融实验的结果（AgentRunbook-R）：
- **问细节的题，要靠原文。** 去掉原文切片后，准确率从 66.1% 掉到 28.6%（小规模），从 63.0% 掉到 23.3%（中规模）。
- **问流程的题，要靠提炼。** 去掉笔记后，准确率从 52.8% 降到 48.1%（小规模），从 47.2% 降到 39.6%（中规模）。论文原话："流程类问题受益于把轨迹经验整合成可复用的事件和笔记。"
- **"坑"类题目结果混杂，** 而且样本小。
- 论文**没有**测偏好、知识更新和拒答。所以它只能说明"发生了什么"这一层，说明不了长期知识。

### Letta："文件系统就够了吗？"（2025-08，R）

Letta 把对话历史直接存成文件，给 agent 四个文件工具，其中包括语义搜索。在 LoCoMo 上，用 gpt-4o-mini 得了 74.0%。mem0 当时自报的最好成绩是 68.5%。

需要注意：
- 两边都是厂商自己报的数字。mem0 现在自报 92.5%。
- LoCoMo 不测知识更新。
- 所以这个结果只能作为方向上的参考。

### 已经读过的方案（S）

- **trace-memory**：原文是唯一的事实来源。中间层是 Fact，即话题切片，要求"还原当时的情景"。它主要给压缩用；跨会话不注入，只能检索和按地址读取。Knowledge 层很薄。证据链是 knowledge → fact → 原文。
- **Pi OM / Mastra OM**：中间层是带日期的观察日志，只追加，攒到一定量再反思整理。
- **mem0 v3**：重度提取的代表。但它把提取改成了一次调用，只追加，"把能力花在理解输入上"。

## 2. 对照我们已经定下的规则

| 层 | 已有的决定 | B2 还剩下什么要定 |
|---|---|---|
| **长期知识** | ADR-0003 写入门槛很严，宁缺毋滥；ADR-0004 每条都带原话引用 | 已经是"少提取"，不需要再定 |
| **现状** | ADR-0008：一份小快照 | 不需要再定 |
| **发生了什么** | ADR-0009：压缩时要用到"已处理部分的摘要" | **摘要做多细？原文要不要保留，怎么检索？** |

## 3. 真实需求（transcript 标注实验）

我问"…来着？"的时候，想找的是过去的 bug、测过什么、当初怎么讨论的，或者某个具体数字，比如"全量要几小时"。这些都是**细节**，对应 LongMemEval-V2 里要靠原文才能答对的那一类题。
