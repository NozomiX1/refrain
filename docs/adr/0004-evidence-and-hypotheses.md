# 0004. 用户模型的证据：原话与推断分级，推断只作假设

- 状态：采纳（2026-10-22）；认识状态在原话、推断之外加了第三种"观察"（从工具结果或 Claude 的操作里看到的事实和教训，不能写成规则），见 [design.md](../design.md) 6.5；第一版简化见 [ADR-0011](0011-v1-scope-cuts.md)：推断不设次数门槛、"假设"状态、确认流程和作废期限，只靠提示词规则约束；知识直接指向原文
- 日期：2026-10-22
- 相关：[questions.md](../questions.md) A3 · [research/a3-evidence.md](../research/a3-evidence.md) · [ADR-0001](0001-positioning.md)（**细化**差异点 1，不取代）· [ADR-0003](0003-admission.md)（写入标准）

## 背景

ADR-0001 的差异点 1 要求："每条记忆都有我本人的原话作依据"。但愿景里还要"了解我的行为"：有些偏好我从没说出口，只是用行动表现出来。只认原话，就会漏掉这类信号。ADR-0001 把这个张力留到问题清单阶段处理。

ADR-0002、ADR-0003 又推迟了两个问题到这里：重复出现算不算证据，记忆里写不写来源。

调研了 6 篇论文的全文（AdaMem、Personalization Mirage、TRACE、Belief-Based Memory、ToM-SWE、Beyond Recall），以及 trace-memory、Magic Context、Letta Code、CC auto memory 的做法。

## 考虑过的选项

1. **只认原话**（ADR-0001 的字面意思）
   - 问题：漏掉没说出口的偏好，"了解我的行为"做不到。Beyond Recall 也说明，只记事实不够，还要有"这个人怎么做判断"的解读层。
2. **原话和推断同等对待**（Magic Context、Letta、ToM-SWE 基本是这样）
   - 问题：AdaMem 的对照实验里，只靠推断时，46.1% 的更新偏离了真实偏好，典型的错误是规则定得太宽。推断一旦被当成事实，就会出现"超出证据"（Personalization Mirage：41.6%）。
3. **原话和推断分级，推断只作假设**（选这个）

## 决定

**每条用户相关的先验知识，都要标明认识状态，并链接到证据：**

| | 原话 | 推断 |
|---|---|---|
| **是什么** | 我明确说过的：指令、纠正、陈述的偏好，以及对某个提议的明确同意 | 从我的行为模式中归纳出来的 |
| **门槛** | 说一次就够 | 必须在**多次、彼此独立**的场合出现 |
| **范围** | 不扩大：在什么场合说的，就只在什么场合适用。问句不算立场；Claude 的提议不算我的决定，除非我明确同意 | 写明它是从哪些场合归纳出来的 |
| **证据** | 链接到原话 | 链接到每一次的证据。**不允许没有证据的推断** |
| **地位** | 可以用 hook 强制执行（具体哪些，见 C3） | **只是假设**：注入时标明是推断，不用 hook 强制执行；和原话冲突时以原话为准 |
| **升级** | — | 在合适的时候问我一句"我注意到你好像……，对吗？"。我确认后升级为原话；我否认，就作废 |

**证据只认我本人的条目。** 计数和链接都只能用我自己的消息（以及我在 CC 里做出的拒绝、打断这类操作）。工具输出、网页内容、Claude 自己说过的话，都不能作为用户模型的证据，也不能计入"重复出现"的次数。

**来源分两层处理：**
- **存储时，保留完整的引用链：** 先验知识 → "发生了什么"里的片段 → 原始消息。
- **注入时，只给原则和认识状态，** 加一个可以追查的 ID，不带原话和事件经过。需要时再按 ID 去查。

**这次不定的：**
- 推断需要出现几次：先不定，留给实验和实际使用来调。
- 什么时候问、怎么问、多久问一次，才不会烦人：新增为问题 C5。
- 哪些原话适合用 hook 强制执行：C3。

## 理由

- **分级，是为了同时满足"忠实"和"了解我的行为"。**
  - 推断有价值：ToM-SWE 的推断被开发者普遍接受，Beyond Recall 证明了"解读层"的作用。
  - 推断又更容易错，所以只给它"假设"的地位。错了的代价因此有上限：不会被强制执行，也不会压过我说过的话。
- **风险不在推断本身，而在推断被当成事实。** Personalization Mirage 发现，要求模型给推断附上证据时，超出证据的比例只有 0.7–4.6%；不加约束地生成时，平均是 41.6%。作者也建议"没有证据链接的推断，要当作假设而不是事实"。
- **原话说一次就够，但不扩大范围。** 我明确说出口的，本身就是最强的证据（AdaMem：直接陈述带来更可靠的学习）。最容易出错的地方是范围被泛化：AdaMem 和 TRACE 都遇到过规则定得太宽的问题。
- **只认我本人的条目，是为了防投毒。** Belief-Based Memory 的实验里，如果只按出现次数算，攻击者写 10 条假信息就能推翻 4 条真的；按来源限定可信度后，攻击成功率降到 0%。这条规则在 CC 里也容易落地：transcript 里本来就区分 user、assistant 和工具结果。
- **存储有来源、注入不带故事，兼顾了两边。**
  - 引用链是忠实、使用归因（差异点 2）、防投毒、让我能修正的基础。
  - 注入时只给原则，采纳了 Letta 的顾虑："模型会模仿示例里的细节"；同时也省 token。
- **"问一句"借鉴了 ToM-SWE**（不确定时问用户），这是让假设变成确定知识的最直接的办法。

## 后果

好的方面：
- ADR-0001 留下的张力解决了。差异点 1 的"忠实"细化为："**每条都链接到我本人的证据，并标明是原话还是推断**"。
- 认识状态这个字段可以用来评测：推断被我确认的比例，就是推断的准确率。

要付出的代价和风险：
- **认识状态多了一个字段，** 写入、整理（B 段）、注入（C 段）都要处理它。
- **"问一句"如果设计不好，会很烦人。** 问得太频繁、时机不对，都会伤害体验。这一点放到 C5 单独设计。
- **"不扩大范围"会让原话的适用面偏窄，** 有时需要我再说一遍。这是有意的取舍：我宁可再说一遍，也不要被错误地泛化。
- **只认我本人的条目，** 我转述的别人的话、我贴进来的文本，也会被记成"我说的"。CC 的 transcript 分不出这一点，需要在提取时由模型判断（trace-memory 的提示词里有类似的要求）。

## 什么情况下推翻

- 实际使用中发现，推断被我确认的比例很高，而"只是假设"的地位让它们长期起不了作用 → 考虑放宽，比如确认率高的类型可以自动升级。
- 发现"不扩大范围"导致我反复重复同样的话 → 调整原话的泛化规则。
- 问一句的设计做不好（C5），用户体验明显变差 → 推断改为只在用户主动查看时展示。
