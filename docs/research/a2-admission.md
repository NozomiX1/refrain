# A2 调研：写入标准，什么能从"发生了什么"升级成先验知识

> 目的：回答 A2。把定位里的"会影响将来的东西"变成可以操作的规则。
> 日期：2026-10-22
> 证据等级：**S** = 源码和提示词（克隆版本同 [a1-landscape.md](a1-landscape.md)）。CC auto memory 的规则来自本会话系统提示里的写入指引。
> 前提：[ADR-0002](../adr/0002-memory-layers.md)，记忆分两层。A2 判断的是"发生了什么"里哪些能升级成先验知识。

## 1. 各家的准入问题

| 项目 | 准入问题（原文大意） |
|---|---|
| trace-memory | 没有它，读者还能不能意识到相关的东西存在、正确理解当前的看法、恢复所需的判断或行动？按"**忘了会有什么后果**"排序：会不会丢掉讨论主线、误解用户、选错、重走被否决的路、漏掉未完成的事、大大增加恢复成本 |
| Pi OM（reflector） | **future-agent utility test**：将来的助手是否需要在压缩后的上下文里自动看到它，才能避免错误决定、重复劳动、违反用户偏好？ |
| Magic Context（events） | 如果忘了这个发现，将来的会话会不会**再踩一次同样的坑**？ |
| Magic Context（PROJECT_RULES） | 新来的开发者或 agent 在日常的重复工作中，是否需要遵守它才不会把事情弄坏？ |
| Hermes | 只写**对每个会话都成立、和具体任务无关**的东西 |
| Letta Code（reflection） | 优先级依次是：错误和纠正 > 偏好和模式 > 值得保留的新事实 > 和现有记忆的矛盾 > 可复用的流程 |

**共同点：** 都是反事实测试，问"没有它，将来会差在哪"。这和定位里"会影响将来的东西"是同一个意思。

## 2. 各家的排除项

| 排除项 | 谁明确写了 |
|---|---|
| 能低成本重新得到的：代码、文件内容、git 历史、命令列表 | Letta、Hermes、CC auto memory、trace-memory（"只丢细节就留在原处"） |
| 当前任务的状态、最近的活动、临时待办 | Hermes、Letta、Pi OM、Magic Context、CC auto memory |
| 和已有记忆重复，只是换了措辞 | 全部 |
| 过程记录：查了哪些文件、跑了什么命令、失败的尝试 | Pi OM、Magic Context、claude-mem（这一条属于它的第一层） |
| 只发生一次、含糊的单个事件 | Letta："只根据一个模式或一条明确指令更新" |

## 3. 偏向：宁缺毋滥，还是宁多勿漏

| 立场 | 谁 | 原话 |
|---|---|---|
| **宁缺毋滥** | Pi OM | "过度反思也是一种记忆失真：它让临时细节看起来很持久，并把将来真正需要的少数事实挤出去。"；"拿不准就不写。" |
| | Hermes | 常驻记忆只有 2,200 + 1,375 字符 |
| | Letta | "健康的文件会随时间变得更概括；狭窄规则的数量不断增长，是失败的信号" |
| **宁多勿漏** | mem0 v3 | "每一条值得记住的信息都必须提取，漏掉一条就意味着丢失上下文" |

**mem0 为什么不一样：** 它没有"发生了什么"这一层，漏掉一条就永远丢了。而有第一层的项目，漏掉的东西还在原文里，可以检索，也可以等以后整理时再补。

## 4. 分歧

**仓库里已经记录过的东西，记忆里还写不写？**
- 完全不写：Letta、Hermes、CC auto memory。
- 写"理解 + 指针"：trace-memory。原话："只有名字和地址是不够的；一旦能理解和定位，就停止添加细节。"它的例子是保留最终设计的理由，再加一个"详见某文档"的入口。
- 写具体的值：Magic Context 的 CONFIG_VALUES 类专门存配置值。

**写成原则，还是保留具体情况？**
- Letta："写原则和理由，不写事件"。纠正反复出现时，就给原则附一个对比示例。
- trace-memory："要保留有用的教训：一条路线被否决后，它为什么失败、是怎么知道的，仍然可能影响判断"。
- 这个分歧和"写不写来源"是同一个问题，放到 A3 讨论。
