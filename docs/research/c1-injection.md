# C1 调研：什么时候注入、怎么注入

> 目的：回答 C1，顺带回答 C2（冻结快照，还是即时生效）。
> 日期：2026-10-23
> 证据等级：**R** = 官方文档（code.claude.com/docs/en/hooks、/mcp，2026-10-23 抓取）· **O** = 本会话里直接观察到的。

## 1. CC 提供的注入通道（R）

| 通道 | 什么时候生效 | 上限 | 备注 |
|---|---|---|---|
| **SessionStart hook 的 `additionalContext`** | 来源分 `startup`、`resume`、`clear`、**`compact`**、`fork` 五种 | **每个字符串最多 1 万字符**。"每个字符串单独计算，即使同一个事件有多个 hook" | 超出上限的部分会存成文件，只保留前 2000 字符作预览，而且"不会要求 Claude 去读那个文件"。内容会包在 system reminder 里，放在对话开头 |
| UserPromptSubmit hook 的 `additionalContext` | 每次我发消息时 | 同上 | 和我的消息放在一起 |
| MCP server 的 instructions | 会话开始时，进入系统提示 | 4096 字符 | 只在我们有 MCP server 时才能用 |
| MCP 工具描述 | 工具被加载时 | 延迟加载的工具 16384 字符，预先加载的 4096 字符 | |

另外两条：
- **写法有讲究。** 文档说："用陈述事实的写法，不要写成命令式的系统指令……写成带外系统命令的样子，可能会触发 Claude 的提示注入防御。"
- **压缩后能重新注入。** 本会话压缩之后，出现过 `SessionStart:compact hook success`（O），说明 `compact` 来源确实会触发。

## 2. 和已有决定的关系

| 已有决定 | 对 C1 的要求 |
|---|---|
| ADR-0008 | 现状每次都注入，压缩时一定带上 |
| ADR-0010 | "发生了什么"不注入，只供检索（C6） |
| ADR-0013 | 长期知识的上限：全局 4k token、每个项目 15k token。实测现在合计约 3k–6k token |
| ADR-0009 | 会话中途写进去的新知识，压缩之后要能看到 |

## 3. trace-memory 在 CC 上怎么注入（S，2026-10-23 补充）

- **切片绕过 1 万字符上限。** `hooks.json` 在 SessionStart（`startup|resume|clear|compact`）上注册了 24 个 hook，每个只输出第 i 片，每片不超过 1 万字符，合起来约 24 万字符。整份内容只渲染一次并缓存，24 个 hook 都从同一份结果里读，避免拿到不一致的版本。
- **预算按 token 算。** 默认值是全局 4k、项目 15k、会话 1k。迁移代码显示，旧的项目默认值 10k 被专门升级成了 15k。
- **两次压缩之间不持续更新。** UserPromptSubmit 上也注册了 24 个切片，但只在会话中途打开记忆时做一次性补充（`/trace on`、`/trace project`）。README 写着，早期"持续的前台更新"已经被"初始注入 + 一次性补充"取代。
- **子 agent 的情况。** fork 复用父会话的提示词；普通子 agent 自己组装提示词，不带记忆。
- **压缩的两条路。** 接管 CC 压缩时，用自己拼装的内容替换掉 CC 的总结；接管失败时，退回 CC 原生的总结，再用知识补充。
- **压缩时放进去的摘要（fact）有 10k token 的预算**，另外附上一定范围内的摘要标题。
