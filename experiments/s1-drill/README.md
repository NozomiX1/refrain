# s1：第一次端到端跑书记员

对应实现第 2 步（design.md 8.4）。要验证的是：mod 能在主会话每轮结束时起书记员子 agent，书记员能调用 submit，校验通过后写进数据库，完成通知被拦下，简报文件跟着更新。

做法：在 `work/todo/` 建一个单独的 git 仓库（命令行待办工具，内容是我们自己写的，可以公开），用 `tools/cc-start.sh` 在 tmux 里开交互式 CC（Haiku 5.5），加载本仓库作为插件。数据目录指到 `work/refrain-home/`，触发阈值调到 1500 字（`REFRAIN_MIN_CHARS`），不碰真正的 `~/.refrain`。原始数据（transcript、子 agent 的 transcript、数据库）在 `raw/run1/`，只在本机。

剧本三轮：
1. "加一个 done 子命令，先说说你打算怎么改，别急着动手。"
2. "两点都按你的默认来……以后在这个项目里，提交说明一律用中文。这几轮你可以直接改 README，不用先问我。现在动手吧，改完提交。"
3. 第 2 轮 auto mode 的分类器出故障，Edit、Write 全被拒（和 refrain 无关），我把权限切成自动接受编辑后："按刚才的方案接着做，改完跑测试，再提交。"

## 结果（2026-10-25，CC 2.1.310）

| 检查 | 结果 |
|---|---|
| 每轮结束起书记员子 agent | 3 轮起了 3 次，界面下方的 agent 列表里能看到 `refrain:scribe` |
| 书记员调用 submit | 3 次都是第一次提交就通过 |
| 完成通知被拦下 | 3 次都拦下了，屏幕上一行灰字 `Prompt dropped by a hook: refrain：记忆已整理`，主会话没有多跑一轮 |
| 写进数据库 | 3 份摘要；1 条知识；项目现状、本会话现状各有更新，旧项都有交代 |
| 简报文件 | `briefings/<项目>.md` 跟着更新，头部和 model-facing/briefing.md 一致 |

**写得好的地方：**
- "先说说你打算怎么改，别急着动手"放进了本会话现状，作为临时指令，没有写成长期规则。
- 第 1 轮停在 Claude 的提议上，书记员记了一项进度"等用户回答两点：……"，下一轮只看到"两点都按你的默认来"也接得上。
- "以后在这个项目里，提交说明一律用中文"写成了项目级规则（原话），`scope` 是 project。
- 授权"这几轮可以直接改 README"进了本会话现状，出处是我的原话，还写清了"不用先问"只针对 README，改代码靠的是"现在动手吧"。

**发现的问题：**
1. **书记员每次输出 8k–16k token**，大多是思考。它继承了主会话的 effort（xhigh）。按 Haiku 单价，每次约 $0.008–0.011，三次合计约 $0.03。`$.agent.register` 可以设 `effort`，设多少归 E7。
2. **主模型自己写了 CC 自带的记忆文件**（"已存下'提交说明用中文'这条偏好"）。原因有两个：这个测试项目没关 auto memory（`settings.local.json` 是开会话之后才写的，没生效）；而且还没有知识时简报是空的，根本不注入，简报里"用户说记住时不需要写文件"那句它看不到。search 的工具说明里也有这句，而且一直可见，第 3 步注册 search 后就有了；4.11 说的"启用插件时关掉 auto memory"也要做进启用流程。
3. **"这几轮可以直接改 README"被提前结束了**：README 改完那一轮，书记员把这项授权标成了 done。原话的有效期是"这几轮"，不是"改完一次"。属于 B9 那类边界，放进 E7 用真实会话校准。
4. 用量能从子 agent 的 `turn.complete` 拿到（写进了 `runs.usage`）。注意子 agent 的 transcript 里同一条回复拆成多行、每行都带同一份用量，直接相加会重复计算。

花费（按 API 价折算）：书记员三次约 $0.03；主会话三轮 Haiku 约 $0.03（状态栏：新写入缓存 65k、读缓存 474k、输出 22k token）。合计约 $0.06。

## 第二次：新会话、压缩、检索（2026-10-25）

第 3 步做完后（注入、交接、search 和 read），在同一个项目里开新会话 S2，三轮加一次压缩。原始数据在 `raw/run2/`。

| 检查 | 结果 |
|---|---|
| 新会话看得到上次的记忆 | 问"上次做到哪了、提交说明有什么约定"，7 秒答对，没翻文件：done 子命令、todos.json 加锁待定、提交说明用中文 |
| 不问也能用上 | "加 undo，做完提交"：提交说明用的中文。不过 git log 里上一条也是中文，单凭这次分不清是记忆还是照着学 |
| 不再写 CC 的记忆文件 | 这次没写（auto memory 已关） |
| 压缩 | `/compact 重点保留 undo 的实现方式`：0.33 秒，不调模型，5.1 万 token 压到 3100。transcript 里是我们拼的消息加上原样保留的 undo 那一轮 |
| 压缩后接着做 | "undo 刚才是怎么实现的"一句话答对，来自原样保留的尾巴 |
| 检索 | "上个会话里 done 越界怎么处理、为什么"：先 `search("done 编号 越界\|越界\|退出码\|stderr")`，再 `read("M2")`、`read("M1")`；回答分清了哪些是记录里的、哪些是它现在补的 |

**发现一个严重的 bug（已修）：** 压缩之后，第 4 次运行被撤销了，第 5 次又把 S2 从头整理了一遍。原因是原样放回的尾巴副本里，有一条的 `parentUuid` 指回了压缩前的原件，读取器沿着它往回走，绕过了压缩边界，书签所在的那一段就不在生效路径上了，被当成回退。e0 只看了副本换了新 uuid、保留原时间戳，没看父链。修法：往回走时碰到副本（边界之后、时间戳早于边界），直接跳到那个边界。补了测试；在本机全部 transcript 上重跑，轮数、用户消息数、工具配对都不变，生效路径上少掉的只有 `/compact` 命令的输出行，本来就会被丢掉。这次演练的数据库里 S2 的记录因此重复整理过一次，留着不改，作为这个 bug 的样本。

花费（按 API 价折算）：主会话三轮约 $0.04，书记员两次约 $0.01。

## 第三次：外壳（面板、暂停、拦自动压缩、空闲压缩、--resume）（2026-10-26）

第 4 步做完后跑。分两段：会话 S3 测面板、启用、暂停和恢复、自动压缩被拦；会话 S4 把缓存时长调成 1 分钟（`REFRAIN_IDLE_TTL_MS`，只给测试用），测空闲压缩和 `--resume`。两段都同时加载 refrain 和 refrain-timer。原始数据在 `raw/run3/`。

| 检查 | 结果 |
|---|---|
| 启用时关掉 auto memory | 先从项目设置里删掉 `autoMemoryEnabled`，会话一开始 refrain 就把它加了回去，原有的权限设置都保留 |
| `/refrain` 面板 | 打开、方向键滚动、Esc 关闭都正常；知识、项目现状、书记员状态、花费、知识规模都对 |
| 暂停和恢复 | 往数据库里插 3 条失败的运行记录，下一轮就暂停：状态栏显示"已暂停（连续失败 3 次，/refrain resume）"，提示了一次；`/refrain resume` 后回到"空闲"，计数清零 |
| 状态栏 | 演练里实时显示 `refrain ≈$0.01 45% 整理中/空闲` |
| 拦下 CC 的自动压缩 | 把阈值调低后，压缩被拒绝，屏幕上显示拒绝的原因 |
| 空闲压缩 | 上一轮结束约 1.5 分钟后，refrain-timer 发起压缩，走我们的交接：5.5 万 token 压到 947，0.25 秒 |
| `--resume` | 恢复后第一次请求的上文 42,472 token，和新会话开头差不多，远小于压缩前的 55,330：恢复出来的是压缩后的上文，没有被尾巴副本的错误父链带偏（自检清单第 7 项） |

**发现并修好的问题：**
1. **主会话的一轮结束时如果书记员还在跑，结尾那一行会一直显示"Waiting for 1 background agent to finish"**，直到我下一次发消息（这次挂了 4 分 23 秒）。这一轮其实早结束了，也不影响打字和书记员；是 CC 的这一行在等书记员的完成通知，而通知被我们拦掉了。类型说明里写明插件可以为自己的 agent 重画这一行：等的全是书记员时，画成正常的"✻ 用时多少 · done 时间"。重现后确认生效。
2. **书记员的上下文里也被注入了一份"记忆"块**（约 935 字，它的输入里本来就有全部知识，开头的说明还是写给主模型的）。注入事件不带 agent 编号，改为：起书记员之前记一笔，30 秒内的第一次注入算它的，跳过。确认之后书记员的上下文里没有了。
3. 面板开头是写给模型看的那段说明，我看面板用不着，还把内容挤到了第二屏；改为从第一个分节开始显示。
4. 提示里写了"refrain："前缀，引擎自己又加了一次插件名，变成"refrain: refrain：……"；去掉了我们的前缀。

**另外看到的：**
- S3 一开始用的还是拦截之前的代码，那时真的发生了一次自动压缩；这个会话还没有摘要，refrain 交给了 CC 原生压缩，就是设计里的退路。
- 插件发起的压缩，在 CC 的压缩记录里标的是 `manual`，和我手动 `/compact` 分不开；只有我们自己的日志里写着 `plugin`。
- 上下文接近阈值时，CC 会先把 Read 的返回截短（"剩下的内容超出了本轮剩余的上下文"），并清掉旧的工具结果，不一定马上走到自动压缩。

花费（按 API 价折算）：书记员 4 次约 $0.02；主会话两段约 $0.05。合计约 $0.07。
