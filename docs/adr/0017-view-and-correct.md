# 0017. 查看与修正：用面板查看，不经过模型；修正靠在对话里说；快照文件只读

- 状态：采纳（2026-10-23）
- 日期：2026-10-23
- 相关：[questions.md](../questions.md) C7 · [research/c7-view-experiment.md](../research/c7-view-experiment.md) · [positioning.md](../positioning.md)（目标："我能查看和修正"）· [ADR-0004](0004-evidence-and-hypotheses.md)（证据只认原话）· [ADR-0009](0009-writer.md)（只有 worker 写）· [ADR-0015](0015-context-assembly.md)（快照文件）

## 背景

汇总"更新从哪来"的时候，发现漏了一条：我自己直接查看和修正记忆。positioning.md 的目标里写着"每条记忆能追到来源，我能查看和修正。错误的记忆比没有记忆更糟"，但问题清单里一直没有对应的问题。CC 的 auto memory 至少还有 `/memory`。如果我们关掉它又不补上，这一点就比原来更差。

各家的做法分两派：直接改文件（CC、Letta），或者不让人手动改（trace-memory、Pi OM）。

讨论到查看方式时，我问"放在一个位置，还是用命令在终端里显示"。Claude 的回答是：普通的命令输出要经过模型。于是我要求先试一下能不能直接在终端里显示，不行再退回文件。实验结果见 research/c7-view-experiment.md：

- 命令直接输出：整份内容都会进入模型的上下文；
- 插件面板：不进上下文，方向键可以滚动。

## 决定

**1. 查看：用插件面板。** 一个斜杠命令打开面板，显示当前生效的记忆：
- 按"关于我 / 项目知识 / 现状"分组；
- 每条带 ID（比如 K12）、"截至某日"、标明原话还是推断；
- 面板打开时自动获得焦点，方向键滚动，Esc 关闭；另有一个关闭子命令兜底；
- 内容不经过模型，不花 token；
- "Claude 眼中的我"就是"关于我"这一组。

**2. 内容来源：ADR-0015 的快照文件。** worker 每次写入后都会渲染这份文件，面板直接读它。文件开头写明："这是生成的视图，改动请在对话里说"。

**3. 修正：在对话里说。** 比如"K12 记错了，应该是……""恢复 K12""删掉 K7"。
- 我说的话就是原话，worker 照常处理，证据指向我说这句话的那条消息；
- 在当前会话里，这句话已经在上下文中；下一次 worker 运行后，修改就会落盘；
- 被归档的条目还在，`read(K12)` 能看到历史版本，"恢复"由 worker 执行。

**4. 不允许直接编辑快照文件。**

**5. 退路：** 如果插件函数接口在以后的版本里不能用了（它是实验性的），就退回到"快照文件放在固定位置，用编辑器打开"。

## 理由

- **查看的内容必须是原样。** 经过模型显示，模型可能会概括或改写；我想看的恰恰是到底存了什么。而且每看一次都要把整份记忆送进上下文，白白花钱。
- **面板经过实测。** 2.1.308 上，内容不进上下文，方向键可以滚动。trace-memory 的 `/trace` 用的也是同一套面板机制。
- **修正走对话，就不用另开一条写入通道。** ADR-0009 规定只有 worker 写，ADR-0004 规定证据只认原话。在对话里说，两条都能满足。允许直接改文件，就得检测改了哪里、再解析回数据库，而且这次修改没有原话可以作证。

## 后果

好的方面：
- 查看不花 token，看到的就是存的原样；
- 修正不需要新机制。

要付出的代价和风险：
- **依赖实验性的插件函数接口。** 版本一变可能就不能用了，所以留了退路。
- **点 × 关不掉面板**，原因没查明，目前靠 Esc 和关闭子命令。
- **修正不能立刻落盘**，要等 worker 下一次运行。
- **不能直接改文件，** 我用起来可能会觉得不顺手。

## 什么情况下推翻

- 插件函数接口被移除或者大改 → 退回到文件加编辑器。
- 我经常想直接改文件 → 允许直接编辑，把我改动的部分当作原话来处理。
